# 中文合成工单与功能测试集

本目录仅新增数据文件，未导入数据库，未改动业务代码。所有人员、组织、事件和处理结果均为合成演示，不是真实已办结工单。

## 文件怎么用

1. `工单2000条.csv`：在“基础管理 → 历史导入”上传。UTF-8 BOM 编码，字段顺序匹配当前项目导入接口。全部为模拟已解决历史案例，解决方案包括原因、处理和复测要求。
2. `知识库处理指南.md`：50 种根因对应的处理知识。通过知识库上传为草稿，选择产品、模块、分类，检查后发布，再按项目既有步骤重建知识索引。不要用 OCR 识别此文本文件。
3. `测试问题100题.md`：逐题复制到智能助手；JSONL 版本用于后续自动化评测。每个问题独立新建会话，避免上一题上下文影响结果。
4. `测试参考答案.md` / `.jsonl`：人工判分依据，不能上传知识库或作为提问上下文。明确诊断题的 JSONL 包含相关历史案例来源编号；导入后需要将来源编号映射到数据库真实 ID 才能接入项目已有评测器。
5. `工单原因标注.jsonl`：用于自动分析结果核对，不是工单导入文件。
6. `generate.py`：仅重建本目录的数据，不连接数据库或模型；再次运行会覆盖生成文件。

## 导入前先检查基础资料

这批数据以软件协作平台为场景，覆盖用户要求的登录、密码、网络等故障，不是蓝牙耳机产品数据。

- 产品：`演示协作平台`
- 模块：`账号模块`、`账单模块`、`报表模块`、`集成模块`，均属于该产品。
- 分类：`账号权限`、`计费订阅`、`功能使用`、`配置集成`、`性能故障`、`服务不可用`、`数据问题`。

基础资料必须存在且启用，否则项目会拒绝整批导入。不要为了导入改成不相关的耳机产品。重复上传同一批次会被来源编号去重规则拒绝。此处没有自动新增基础资料。

知识库指南涉及多个模块，当前上传界面若必须指定单个模块，建议按指南标题挑选对应内容分别录入四个模块，不要把整份指南错误标为某个单一模块。也可使用本目录 `knowledge/` 下四份已按模块拆分的文件。

## 如何测

- 50 道明确诊断题：给出了诊断证据，检查模型是否区分原因、给出对应措施和复测步骤。
- 50 道追问题：仅描述现象，正确表现是提出必要问题并列出可能原因，不能直接宣布根因。
- 相似案例检索：对明确诊断题核对前 5 条中是否有对应场景，计算场景命中率 Hit@5。每个场景存在 40 条相似案例，不宜直接用“找全 40 条”的 Recall@5 判断质量。
- 自动分析：创建新的待处理工单，把问题放入描述，检查摘要和分类建议。当前历史 CSV 导入不会自动触发每条工单的后台分析。
- 人工评分：原因判断、措施匹配、必要追问、未虚构结果各记 0/1 分；知识问答还需核对引用是否确实支持回答。
- 严重程度是合成场景标签；实际环境必须结合影响范围和业务规则重新核定。

## 数据边界

2000 条由 **50 种根因场景 × 40 条演示变体**组成，变体更换组织、渠道和受影响数量，不是 2000 个独立故障。适合导入、分页、检索和流程冒烟测试。100 道题也源于同一套场景，只能证明这些场景的功能表现，不能作为独立泛化评测或论文中真实业务准确率。

要比较切分策略，应固定文档、模型和问题，分别记录检索命中、证据完整性及答案正确性。这批短案例对长文档切分的区分能力有限，需要另补真实长文档和独立标注题。

本批 CSV 不包含客户账号归属、会员等级或真实对话，因此不能直接用于客户端权限隔离、会员排序或客服转交测试；这些应使用双端服务页面创建的真实演示会话。

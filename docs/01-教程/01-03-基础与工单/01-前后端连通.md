# 第一部分：前后端连通

参考目录：`01-connectivity`。做到页面能检查后端是否可用即可。

## 先理解一次请求

```text
点击“重新检查”
  → App.vue 调用 getHealth()
  → health.ts 发出 GET /api/health
  → Vite 把 /api 请求转给 127.0.0.1:8000
  → FastAPI 找到处理这个路径的函数
  → 返回 {"status":"ok"}
  → App.vue 显示“前后端连接成功”
```

## 第一步：写后端入口

参考 `backend/app/main.py`：

```python
from fastapi import FastAPI

app = FastAPI(title="售后工单智能辅助系统")


@app.get("/api/health")
def health() -> dict[str, str]:
    return {"status": "ok"}
```

| 代码 | 大白话解释 | 能不能改 |
|---|---|---|
| from fastapi import FastAPI | 从已安装的包中拿来 FastAPI 这个工具 | 包名和工具名按库要求拼写 |
| app = FastAPI(...) | 创建一个后端应用，起名 app | app 可改，但启动命令最后的 app 要同步 |
| title="..." | 接口文档里显示的名字 | 可以直接改显示文字 |
| @app.get(...) | 登记一个处理 GET 请求的窗口 | get 是框架方法；其他方法用 post、patch 等 |
| "/api/health" | 窗口地址 | 可以设计，但代理规则和前端请求要配套 |
| def health() | 给处理函数起名 health | 可以改，路由路径不会因此改变 |
| -> dict[str, str] | 提示返回“字符串键、字符串值”的字典 | 是类型描述，不能随便写成无关类型 |
| {"status": "ok"} | 返回给页面的数据 | 是本项目接口约定，前端也依赖 status 与 ok |

## 第二步：启动后端

在 WSL 终端：

```bash
cd /mnt/e/oshino
source /mnt/e/xiangmu/.venv/bin/activate
cd backend
python -m uvicorn app.main:app --reload --port 8000
```

这里必须在 backend 目录。目录里应当能看到 app 文件夹。

`app.main:app` 的前半段表示 `app/main.py` 这个模块，
冒号后半段表示文件里 `app = FastAPI(...)` 创建的对象。

访问 [健康接口](http://127.0.0.1:8000/api/health)。
访问 [接口文档](http://127.0.0.1:8000/docs) 可以看到后端登记了哪些接口。

## 第三步：写前端文件

按源代码中的同名文件填写：

| 文件 | 用途 |
|---|---|
| package.json | 声明依赖和 npm 命令；第一部分沿用已安装的 Vue/Vite 工具 |
| tsconfig.json | 告诉 TypeScript 检查哪些文件、用哪些规则 |
| vite.config.ts | 配 Vue 插件、前端端口、后端代理 |
| index.html | 放一个 id 为 app 的页面容器 |
| src/main.ts | 创建 Vue 应用，把 App.vue 放进这个容器 |
| src/api/health.ts | 发请求，检查 HTTP 状态和返回内容 |
| src/App.vue | 管理检查过程，并把结果显示到页面 |

`main.ts` 的 `import App from './App.vue'` 指的是同目录下的 App.vue。
你之前的报错就是这个文件还没有创建；文件名大小写也要一致。

Vite 配置是 TypeScript，代码块语言应看作 ts，不是 YAML。

## 第四步：读懂 App.vue 的三个区块

```vue
<script setup lang="ts">
// 放变量、函数和事件处理代码。
</script>

<template>
  <!-- 放页面结构。 -->
</template>

<style scoped>
/* 放当前组件的样式。 */
</style>
```

`script`、`template`、`style` 是 Vue 单文件组件的区块约定。
`lang="ts"` 说明使用 TypeScript；`scoped` 表示这些样式主要作用于当前组件。

源代码里的三个变量：

- `isChecking`：现在是不是正在等请求，用于禁用重复点击。
- `healthStatus`：成功后拿到的返回值。初始 null 表示“还没有成功结果”。
- `errorMessage`：需要展示的错误。初始空字符串表示“目前没有错误信息”。

`ref` 是 Vue 提供的工具。脚本里改 `isChecking.value`，
模板里可以直接写 `isChecking`。

`try` 放请求，`catch` 显示能处理的 Error，`finally` 无论成功失败都结束等待状态。
未识别的非 Error 异常继续抛出，不转换为成功。

`v-if` 是按条件显示内容；`@click` 把点击动作接到函数；
`:disabled` 根据变量动态决定按钮是否能点。

`health.ts` 在收到 JSON 的地方检查一次格式，页面直接使用已经检查过的结果。
5 秒是本示例选择的连通性等待上限，不是 FastAPI 或 Vue 的强制值。

## 第五步：启动前端

新开一个 WSL 终端：

```bash
export PATH="$HOME/.local/bin:$PATH"
cd /mnt/e/oshino/frontend
npm install
npm run typecheck
npm run build
npm run dev
```

依赖已经安装且 package.json 未变时，不必重复安装。
打开 [前端页面](http://127.0.0.1:5173)。

## 完成条件

- 健康接口返回 HTTP 200 和 {"status":"ok"}。
- 前端显示连接成功。
- 停止后端、重新检查时显示错误；恢复后端后可以再次成功。
- typecheck 与 build 成功退出。

到这里第一部分结束。显示“连接成功”只说明这条 HTTP 链路可用。
数据库连接由第二部分的迁移和登录过程验证。

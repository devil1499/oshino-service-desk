# 第二部分：数据库、登录与基础配置

参考目录：`02-foundation`。本阶段增加 PostgreSQL、数据库表、管理员、客服账号与基础配置页面。

## 先知道新增工具各管什么

| 工具 | 大白话解释 |
|---|---|
| PostgreSQL | 真正把账号、产品等数据保存到硬盘 |
| SQLAlchemy | 让 Python 通过模型和查询来操作数据库 |
| psycopg | Python 与 PostgreSQL 沟通的驱动 |
| Alembic | 记录数据库结构变更，按版本建表或加字段 |
| Pydantic | 检查传进后端的数据 |
| pwdlib / Argon2 | 计算并核对密码哈希 |
| PyJWT | 生成和核对登录令牌 |
| Vue Router | 根据前端网址显示不同页面 |
| Pinia | 让登录信息能被多个页面共同使用 |
| Element Plus | 提供输入框、按钮、表格等页面组件 |
| Zod | 在前端收到 JSON 的边界集中检查返回格式 |

Zod 用来处理当前多个接口的响应结构，避免每个页面重复手写字段检查。
这些库都在本阶段的依赖清单中，AI、OCR 依赖等后续再接入。

## 第一步：准备 PostgreSQL

本教程使用 WSL Ubuntu 本机 PostgreSQL，监听本机 5432 端口。
下面安装命令由你在终端执行；代码包不会替你安装系统服务。

```bash
sudo apt update
sudo apt install postgresql
sudo service postgresql start
sudo -u postgres psql
```

进入 psql 后，提示符会变为类似 `postgres=#`。下面这些属于 SQL/psql 命令：

```sql
CREATE ROLE after_sales LOGIN;
\password after_sales
CREATE DATABASE after_sales OWNER after_sales;
CREATE DATABASE after_sales_test OWNER after_sales;
\q
```

执行 `\password` 时输入你自己设置的数据库密码，不会把明文写进上面的 SQL。
这是首次创建时的命令；已经有相同用户或数据库时，不要重复创建或删除已有数据。

`after_sales` 在 CREATE ROLE 中是数据库用户名，在 CREATE DATABASE 中是数据库名，
二者碰巧取了同一个名字。`after_sales_test` 是单独用于测试的数据库。
这是项目命名，可以改，但连接地址和测试命名规则也要同步。

官方资料：[Ubuntu 安装说明](https://www.postgresql.org/download/linux/ubuntu/)、
[psql 命令说明](https://www.postgresql.org/docs/current/app-psql.html)。

## 第三步：安装 Python 依赖并生成本地配置

在 WSL：

```bash
source /mnt/e/xiangmu/.venv/bin/activate
cd /mnt/e/oshino/backend
python -m pip install -r requirements-dev.txt
python -m app.configure
```

程序会让你输入刚才 PostgreSQL 的 after_sales 用户密码，并生成 backend/.env。
它会给 JWT 生成随机签名密钥、编码密码中的特殊字符，也不会覆盖已有 .env。
已存在的配置可在编辑器里调整。

后端只从本阶段的 `backend/.env` 读这些配置：

| 字段 | 意思 | 是否自己改 |
|---|---|---|
| DATABASE_URL | 数据库的连接地址 | 按你的数据库用户、密码、主机、端口、库名填写 |
| JWT_SECRET | 给登录令牌签名的随机密钥 | 由 configure.py 生成，保存为本地配置 |
| ACCESS_TOKEN_MINUTES | 登录凭证有效期，单位分钟 | 当前取 480（8 小时），允许 1～1440；不是框架固定值 |

连接地址格式：

```text
postgresql+psycopg://用户名:经过URL编码的密码@主机:端口/数据库名
```

`postgresql+psycopg` 是本教程选择的数据库与驱动组合。
更换数据库不是只改这一小段文字，模型、迁移和验证也会受影响。

缺少配置、密钥过短或数据库连接失败会直接报错，不会生成假连接或默认登录成功。
.env.example 是格式示例，里面的中文占位内容不能作为实际密码。

## 第四步：真正建表

```bash
python -m alembic upgrade head
```

大白话：把 migrations/versions 里还没执行的建表脚本按顺序运行。
迁移文件相当于“数据库结构施工记录”，Alembic 会在数据库里记录已执行的版本。

本阶段应出现：users、products、product_modules、ticket_categories，
以及 Alembic 自己的版本表 alembic_version。

- `models.py`：Python 代码希望表长什么样。
- `migrations/versions/*.py`：真正改变数据库结构的版本脚本。
- 修改模型以后，不会自动把已经存在的表改好；需要新迁移。
- 普通启动应用时不会自动删表，也不会用 create_all 掩盖迁移遗漏。

## 第五步：初始化管理员

```bash
python -m app.seed --username admin --display-name 管理员
```

输入并再次确认自己的管理员密码。用户名可改，至少 3 位，只用字母、数字和下划线。
显示姓名可以用中文。密码要求 8～128 位，这是本项目设置的规则。
输入不合格时，命令会说明哪个字段有问题，但不会输出输入的密码。

初始化命令还会补齐 7 个默认问题分类。
同名账号已存在时会报错，不覆盖原账号或密码。

这里有两个不同密码：

1. 数据库密码：后端连接 PostgreSQL 使用，保存在 backend/.env。
2. 管理员登录密码：你在网页登录使用，数据库里保存它的哈希。

两者用途不同，不能把 JWT_SECRET 当成网页登录密码。

## 登录过程用大白话串起来

```text
LoginView 收集用户名和密码
  → stores/auth.ts 调用登录接口
  → 后端查 users 表
  → 用 password_hash.verify 核对输入密码
  → 生成带有效期的 JWT
  → 前端把令牌和用户信息存入 Pinia
  → 以后请求加 Authorization: Bearer 令牌
  → 后端核对签名、有效期、账号是否仍启用
```

前端只隐藏菜单不能实现权限。后端的 require_admin 才负责拒绝客服越权操作。
所有请求还要确认账号仍然启用，所以停用后，已经发出的旧令牌也不能继续访问接口。

当前标签页使用 sessionStorage 保存令牌，刷新后通过 /api/auth/me 核验身份并恢复登录；凭证到期后重新登录。账号和配置已经保存到 PostgreSQL，
重新登录后仍能看到。退出登录清除当前页面里的令牌；没有额外建设服务端令牌注销表。

## 几个关键文件怎么读

- `schemas.py`：请求进来时检查用户名、密码、名称是否合规；响应只开放需要给前端的字段。
- `models.py`：例如 username 唯一，用户角色只有 admin/staff，模块必须关联产品。
- `router.py`：按“检查权限 → 查找或创建对象 → 提交事务 → 返回结果”顺序读。
- `core/security.py`：密码工具、生成令牌、核对当前用户、要求管理员权限。
- `core/database.py`：为每次请求提供数据库会话；结束时关闭会话，未提交修改会回滚。
- `api/http.ts`：复用多个接口共有的请求、超时和错误处理，响应在这里按 schema 校验。
- `api/models.ts`：前端收到的数据长什么样；页面使用已校验的数据。
- `stores/auth.ts`：登录信息的共同存放处。
- `router/index.ts`：决定显示哪个页面，并决定哪些页面要求登录/管理员。

8 小时令牌有效期、5 秒数据库连接超时、10 秒业务请求超时都是示例选择。
库的参数名要按要求写，数值可以在理解影响后按需求调整。

## 第二部分验收

- 无法用错误密码登录。
- 管理员能创建客服，并新增、改名、停用产品/模块/分类。
- 客服能够登录，但不能调用管理员写接口。
- 停用客服后，旧令牌请求被拒绝。
- 重启后端，账号和配置仍在。
- 本阶段 typecheck、build、后端测试通过。

## 运行后端测试


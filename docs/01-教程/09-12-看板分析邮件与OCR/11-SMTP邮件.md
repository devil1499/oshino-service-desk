# 第十一部分：SMTP 邮件

累计工程为 `11-email`。这一部分把“拟好回复、人工核实、发送到测试邮箱、保存结果”接起来。不要把自动分析完成等同于可以自动联系客户。

## 先理解整个过程

客服填写收件人、主题、正文 → 勾选确认 → 浏览器生成本次请求号 → 后端检查工单状态、配置和测试收件人 → 先保存发送记录 → 调用 SMTP → 保存结果。

请求号相当于这一次发送的编号。同一个编号再次提交相同内容，只返回原记录；不会重新发信。同一个编号换正文会被拒绝。网络异常时前端保留编号并锁住正文，让你查原结果。页面刷新会丢失前端内存状态，所以重新登录后应先看发送记录、邮箱和服务端日志，不能直接当作没有发送过。

## 跟写顺序

1. 在 `models.py` 增加 EmailDelivery，新增 `11_email.py` 迁移。数据库保存最终正文、发送人、关联建议、请求号和结果。
2. 写 `integrations/smtp.py`，将邮箱连接和业务接口分开。TLS、认证和超时都在这里处理；授权码只从本机配置读取。
3. 写 `modules/email/router.py`，添加查询和发送接口。先提交数据库记录，再进行无法回滚的邮件投递。
4. 在 `main.py` 注册路由，单进程启动时把上次未完成的发送标为“不确定”。这不代表已经补发。
5. 写 `api/email.ts`、`EmailPanel.vue`，在工单详情页加入邮件区域。在 AI 建议中点击转入邮件后，还能修改内容并重新确认。
6. 配置自己的测试邮箱并迁移数据库，先做拒绝和重复请求测试，最后人工确认发一封测试邮件。

## 哪些写法固定，哪些可以改

| 写法 | 大白话解释 | 修改规则 |
|---|---|---|
| `smtplib.SMTP_SSL` | 从连接开始就使用加密 | 库名固定；服务器、端口按邮箱提供方填写 |
| `starttls(context=...)` | 先连接，再升级为加密 | 使用邮箱提供方支持的方式，不关闭证书校验 |
| `EmailMessage`、`set_content` | 按邮件标准组成正文 | 调用名称固定；主题和正文可编辑 |
| `request_id` | 一次发送的唯一编号 | 字段是本项目接口约定，前后端必须一致；结果不确定时不能换号重试 |
| `confirmed: true` | 用户明确确认发送 | 是业务规则，不能删掉确认步骤 |
| `SMTP_TEST_RECIPIENTS` | 允许投递的测试收件人 | 填你可控制的邮箱，多地址用英文逗号；不能直接改成任意地址 |

## 读懂发送状态

| 状态 | 意义 | 下一步 |
|---|---|---|
| sending | 已记录请求，发送尚未完成 | 稍后刷新原请求或发送记录 |
| accepted | SMTP 服务器接受了邮件 | 查测试邮箱、垃圾箱和退信；不代表最终送达 |
| failed | SMTP 明确拒绝 | 核对错误和配置，人工决定是否另写一封 |
| unknown | 超时、断线或服务中断，无法确认 | 先查邮箱和服务端记录，不自动补发 |

配置或输入在投递前被拒绝时，页面恢复编辑；SMTP 明确完成或拒绝后，点击“开始撰写另一封邮件”才重新编辑。这样不会把再次点击同一个按钮误当作第二次发送。

授权码、服务器原始响应不显示在页面或日志中；错误展示认证失败、收件人拒绝、SMTP 状态码等可处理信息。本部分只支持纯文本、一个收件人，不包括抄送、附件、营销群发或后台队列。已关闭工单拒绝新发送，但已有请求仍可查询原记录。

配置见 [配置与运行](14-配置与运行.md)，操作验收见 [人工验收](15-接口与人工验收.md)。

最终第十二部分已把邮件编辑器放入“客户邮件”页签，切换页签保留草稿，发送历史折叠展示；由 AI 建议带入后会自动切换到邮件页签。页面重载不会恢复内存草稿，离开有编辑内容或未确定请求时会提醒。最终布局见 [界面优化](17-新增区域界面优化.md)。

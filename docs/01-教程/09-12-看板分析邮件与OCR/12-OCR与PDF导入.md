# 第十二部分：OCR 与 PDF 导入

累计工程为 `12-ocr`。OCR 的意思是“把图片里的文字识别出来”。普通 PDF 有可复制的文本时，先直接提取；扫描 PDF 没有文本的页面才转图片识别。最终只是生成知识草稿，识别结果不会自动发布。

## 跟写顺序

1. 按 `backend/requirements-dev.txt` 安装本阶段依赖。新增 PyMuPDF 解析 PDF，Pillow 检查图片，PaddleOCR 与 CPU 版 PaddlePaddle 识别文字。
2. 添加 `core/ocr_settings.py` 和 `.env.ocr.example`。配置是 WSL 中的绝对模型目录，不是 Windows 路径。
3. 添加 `app/prepare_ocr.py`，在终端手动下载模型。下载后填写 `.env.ocr`；网页上传期间不负责下载模型。
4. 添加 `integrations/ocr_worker.py`：检查文件内容、提取 PDF、识别扫描页、拼接正文。
5. 添加 `integrations/document_extract.py`：启动独立 Python 进程，最多等待 180 秒；超时终止子进程并释放临时目录。
6. 修改知识上传接口：检查管理员权限、产品/模块/分类、格式与大小，调用提取器，成功后创建草稿。仍沿用原发布和索引流程。
7. 修改前端上传类型、等待时间与提示；保存期间禁用编辑，避免你新输入的正文被返回结果覆盖。

## 文件限制与原因

| 项目 | 当前值 | 作用 |
|---|---|---|
| TXT、MD | UTF-8，最多 256 KiB | 沿用原文本导入 |
| JPG、JPEG、PNG、PDF | 最多 10 MiB | 控制一次读取量 |
| 图片 | 最多 1600 万像素，内容必须是真实 JPEG/PNG | 避免只改扩展名、损坏图片和过大解码 |
| PDF | 1—20 页、未加密 | 控制处理量；不尝试猜密码 |
| 需要栅格化的 PDF 页面 | 宽高各不超过 2000 点，输出长边最多 4000 像素 | 避免扫描页面转换过大 |
| 提取正文 | 1—100000 字 | 与现有知识文档边界一致 |
| 识别 | 后端 180 秒，前端请求 200 秒；单工作进程内一次一个 | 控制资源占用并留出请求传输时间 |

这些数字是当前学习版的业务限制，可以根据机器和实测调整，但后端、前端提示和测试要一起更新。`subprocess.run`、`TemporaryDirectory`、`page.get_text`、`page.get_pixmap` 是库调用名称，不要随意改名。`rec_texts` 是 PaddleOCR 结果字段，也不能改成中文。

一个 PDF 页面如果有文本层，就使用文本层；同页图片中的额外文字不会再识别。当前没有表格结构还原、版面理解、手写识别保证、自动纠错或扫描文件长期保存。页码以“第 N 页”写入正文，方便人工比对；图片原文件只用于临时处理，来源保存文件名。

## 如何校对

上传 → 等待草稿 → 对照原资料检查标题、数字、错误码、产品名、操作步骤 → 修改正文 → 保存草稿 → 发布已保存正文 → 停止后端并重建知识索引 → 重启后检索验证。

解析失败不会创建草稿。若浏览器网络中断，服务端可能已经保存成功，应先到知识列表核查再决定是否重传。模型路径不存在、引擎初始化失败、文件损坏、无有效文字和超时会显示错误，不用空正文冒充成功。

实现依据：[PaddleOCR 3.x OCR Pipeline](https://paddlepaddle.github.io/PaddleOCR/main/version3.x/pipeline_usage/OCR.html)、[PyMuPDF Page API](https://pymupdf.readthedocs.io/en/latest/page.html)。本教程固定依赖版本；升级后要重新确认模型参数和结果结构。

本机模型下载和真实识别质量需要按 [配置与运行](14-配置与运行.md) 与 [人工验收](15-接口与人工验收.md) 执行，模拟识别测试不能代替这一步。

最终页面按“选择资料→校对正文→发布入库”展示。选好文件和资料信息后点击“识别并创建草稿”；手工录入切换到正文编辑。修改后先保存草稿，再勾选“我已对照原资料核对正文，确认发布”，才能发布已保存正文。文件可选择或拖拽，支持移除，操作图见 [界面优化](17-新增区域界面优化.md)。

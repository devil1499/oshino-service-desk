# 配置与运行：在 WSL 操作

以下命令用于正式工程 `E:\oshino`，WSL 路径为 `/mnt/e/oshino`。第九至十二部分已接入正式代码；逐文件讲解保留阶段参考写法，实际运行以本仓库源码为准。数据库接入及迁移衔接见 [异步数据库与跟写约定](../../02-项目说明/异步数据库与跟写约定.md)。

## 1. 后端依赖与数据库

```bash
cd /mnt/e/oshino
source /mnt/e/oshino/.venv/bin/activate
cd backend
python -m pip install -r requirements-dev.txt
```

当前虚拟环境使用 Python 3.12。CPU OCR 使用 PaddleOCR；若缺少 `libgomp.so.1`，在 Ubuntu 安装 `libgomp1`。Docker 镜像还安装了 OpenCV 需要的 `libgl1` 和 `libglib2.0-0`。OCR 还需要模型权重，安装 Python 包并不等于模型已准备好。本机 PaddlePaddle 3.3.1 开启 oneDNN 时出现 PIR 属性转换错误，因此本阶段 OCR 初始化明确设置 `enable_mkldnn=False`；更换依赖版本后应重新验证实际识别。

在 backend 建立 `.env`，字段参照 `.env.example`。如果已有配置，保留并核对，不覆盖。`DATABASE_URL` 指向自己已创建的 PostgreSQL 数据库；URL 中的密码特殊字符要进行 URL 编码。`JWT_SECRET` 至少 32 字符，使用本机安全随机值，不能使用教程中的示例文字。配置不能提交到 Git 或发进聊天。

停止旧后端，在当前 backend 执行：

```bash
python -m alembic upgrade head
python -m alembic current
```

第九部分新增 `resolved_at`，第十部分新增 `basic_analyses`，第十一部分新增 `email_deliveries`，第十二部分沿用第十一部分数据库版本。第八部分迁移编号是 `07_assistance`；课程编号和迁移编号不必连续，不能为补数字自行改已有版本。

只有空库首次使用才创建管理员：

```bash
python -m app.seed --username admin --display-name 管理员
```

密码在交互提示中输入。已有账号不重复运行初始化。登录后配置产品、模块和分类。

## 2. 模型配置

在 backend 的 `.env.chat` 中填写 `CHAT_BASE_URL`、`CHAT_API_KEY`、`CHAT_MODEL`。地址和模型名以你的提供方实际支持为准，示例值不能保证可用。基础分析只需要聊天模型；相似案例和知识检索另需 `.env.retrieval` 中的 Embedding、Milvus 配置及索引。

模型没有配置时，工单仍会保存，基础分析显示失败；配置好后手动重新分析。历史 CSV 导入不会自动分析每条工单。后台恢复逻辑按**一个 Uvicorn 工作进程**设计，不加 `--workers`；调试重载也会中断未完成任务，需手动重新分析。

## 3. SMTP 配置

在 backend 建立 `.env.smtp`，参照 `.env.smtp.example` 填写：

| 字段 | 填什么 |
|---|---|
| SMTP_HOST、SMTP_PORT | 邮箱提供方公布的服务器和端口 |
| SMTP_SECURITY | `ssl` 或 `starttls`，按服务器要求选择 |
| SMTP_USERNAME | SMTP 登录账号 |
| SMTP_PASSWORD | 邮箱授权码或提供方要求的 SMTP 密码 |
| SMTP_FROM | 与该账号允许的发件身份一致的邮箱 |
| SMTP_TEST_RECIPIENTS | 自己可核查的测试收件地址，多个地址用英文逗号 |

465/ssl、587/starttls 是示例组合，最终以邮箱提供方说明为准。开启该邮箱的 SMTP 服务后再测试，不把普通网页登录密码当作必然可用的授权码。未配置 SMTP 时发送返回明确配置错误，不影响其他模块。

## 4. 准备 OCR 模型

完成第十二部分代码后，在本工程 backend 中首次联网手动运行：

```bash
python -m app.prepare_ocr
```

它下载 PP-OCRv5 mobile 检测和识别模型，最后打印两个目录配置。把这两行写入当前 backend 的 `.env.ocr`。下载速度和源站可用性取决于网络；失败时按实际错误处理，不跳过目录校验。Docker 运行时使用容器自己的模型目录：先构建并启动后端，再运行 `docker compose --env-file .env.docker run --rm backend python -m app.prepare_ocr`，模型保存在 `ocr_models` 卷中。容器配置已指向该卷内目录。

默认目录类似 `/home/你的WSL用户名/.paddlex/official_models/PP-OCRv5_mobile_det`，需要填写真实存在的模型目录。网页只读取已准备的模型。文本 PDF 无需 OCR 模型即可提取；图片和扫描 PDF 需要模型配置。

## 5. 启动后端和前端

后端终端保持在 `/mnt/e/oshino/backend`：

```bash
python -m uvicorn app.main:app --port 8000
```

开发时可加 `--reload`，正式做后台任务或邮件验收时先去掉重载。打开 `/docs` 可查看接口，健康检查地址是 `http://127.0.0.1:8000/api/health`。

另开 WSL 终端：

```bash
cd /mnt/e/oshino/frontend
npm ci
npm run typecheck
npm run build
npm run dev
```

已有匹配的 package.json 和 package-lock.json 时运行 `npm ci`；自行写 package.json 而没有锁文件时先 `npm install`。前端代理继续将 `/api` 转给 8000 端口。前端没有新增图表或邮件依赖。默认端口为 5173；若沿用本机第二部分的 18734，使用 `npm run dev -- --port 18734` 并打开对应地址。

发布知识后，按第六部分流程停止后端，首次建索引运行当前 backend 的 `python -m app.rebuild_knowledge`；已有知识索引时使用 `python -m app.rebuild_knowledge --replace` 更新，再启动后端。该参数替换知识索引，保留业务表和案例索引。不要同时让两个进程使用同一个 Milvus Lite 文件；案例索引仍使用原 `python -m app.rebuild_cases`，已有案例索引的更新同样按原教程使用 `--replace`。

## 6. 测试

在 `/mnt/e/oshino/backend/.env.test` 配置 `TEST_DATABASE_URL`，必须连接独立、名称以 `_test` 结尾的 PostgreSQL 库，不能指向业务库。跟写教程中的参考测试前先确认隔离测试库及迁移已准备好，测试会写入数据；正式第二部分现有测试的临时库机制见其使用说明。

```bash
python -m pytest -q
python -m pytest -q -m postgres
```

第一条运行无需数据库的测试；第二条需要 `TEST_DATABASE_URL`，会创建并清理临时测试库。测试替换聊天和 SMTP 外部调用，OCR 推理测试使用受控识别结果；真实服务按人工验收单验证。不要把测试的通过数量、模拟内容当成毕业论文的效果数据。

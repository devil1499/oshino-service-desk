# 接口与人工验收

## 新增和改变的接口

| 接口 | 权限与作用 |
|---|---|
| GET /api/dashboard?product_id=… | 登录后查询统计，参数可不填 |
| POST /api/tickets | 保存工单时创建基础分析任务，CSV 导入不触发 |
| GET /api/tickets/{id}/analysis | 登录后查看任务、结果和是否过期 |
| POST /api/tickets/{id}/analysis | 未关闭工单可手动重做，正在运行时返回 409 |
| POST /api/tickets/{id}/analysis/adopt | 显式 confirmed=true 后采用最新有效建议 |
| GET /api/tickets/{id}/emails?page=1 | 登录后分页查看发送记录，每页 10 条 |
| POST /api/tickets/{id}/emails | 未关闭工单、人工确认、测试收件人；同 UUID 不重发 |
| POST /api/knowledge/upload | 管理员上传，新增图片与 PDF 支持，成功为草稿 |

原工单权限沿用现有设计：已登录客服和管理员可查看全系统工单；知识上传和发布仅管理员可操作。没有新增租户隔离或“只能看自己工单”的规则。

## 按顺序验收

1. **统计看板**：创建 3 条同产品工单，分别保留待处理、处理中、已解决；核对数量，再换产品筛选。无解决样本应显示“暂无样本”。导入的已解决工单没有真实解决时刻，不得拿导入时刻计算时长。
2. **自动分析**：新建工单，等待摘要、分类和优先级建议；未确认前原字段不变。采用后查看字段和处理记录。改问题描述后旧结果不能采用。断开模型配置后新工单仍保存，分析显示失败；恢复配置后手动重做。关闭工单后禁止重做和采用。
3. **邮件校验**：不勾确认不能发送；未列入测试收件人的地址被拒绝，错误后可以修正输入。配置错误显示准确提示。
4. **真实邮件**：仅向自己控制的测试邮箱发送一封，核对最终主题和正文、发送记录、Message-ID、收件箱和垃圾箱。accepted 只表示 SMTP 接受；有退信时另外记录。
5. **发送异常**：使用测试替身模拟拒绝和断线。相同请求号最多调用一次发送；unknown 不自动重试。页面刷新或连接丢失后先查记录，不直接重新发信。不要为了模拟故障向真实客户反复试发。
6. **OCR 与 PDF**：分别上传清晰中文 PNG、JPG、可复制文本 PDF、纯扫描 PDF；对照原文记录漏字和错字。上传成功只产生 draft，普通客服不能查看草稿。管理员校对后保存、发布、重建知识索引，再从工单检索验证出处。
7. **文件错误**：上传伪装成 PNG 的文本、超过 20 页 PDF、加密 PDF、超过大小限制文件，确认报错。OCR 缺少模型或超时不能生成空的“成功”文档。
8. **回归**：登录、基础配置、工单状态流转、历史导入、相似案例、知识检索、人工采用建议仍按前八部分流程操作。浏览器控制台不能有未处理错误。

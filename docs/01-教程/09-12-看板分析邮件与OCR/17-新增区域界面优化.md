# 分析、邮件与知识上传界面优化

本页记录教学参考工程的最终界面方案。正式工程已将分析卡片、工单页签、邮件编辑器和知识上传步骤接入当前浅色内容区；下方深色截图只展示布局与交互思路，不代表正式工程当前配色或真实数据。正式工程的运行代码以 `frontend/src` 为准。

## 设计与实施计划

- [x] 基础分析改为摘要卡片：状态、摘要、分类/优先级、原因、人工确认分区；正在分析显示骨架，不展示虚假百分比。
- [x] 详情页处理记录、AI 建议和邮件放入可键盘操作的页签。使用 v-show 保留组件和输入；AI 草稿带入后切换邮件页签。

- [x] 知识上传增加步骤、可拖拽文件区、文件信息与移除操作、正文校对和发布确认；未保存修改时禁止发布旧正文。
- [x] 新增共享的未保存提醒，只保存在页面内存；离开路由或关闭标签时提示，切换页签不弹提示。
- [x] 窄屏提供可开关的检索侧栏，统一输入、按钮、焦点和间距；减少动态效果时关闭动画。
- [x] 在浏览器先验证新增页签不存在的失败，再实现并复验：草稿保留、明确拒绝后可编辑、防重复发送、文件移除/校对、未保存提醒和窄屏无横向溢出。
- [x] 运行类型检查与构建；同步逐文件源码块、配置说明、截图、SHA256 和 ZIP。

组件和接口：修改 BasicAnalysisPanel、EmailPanel、KnowledgeEditor、TicketDetailView，补充样式文件和 useUnsavedChanges。后端接口、数据库和依赖清单沿用现有版本。正式工程由用户跟写。

## 小白跟写说明

`v-show` 只控制显示，组件依然存在，因此邮件和建议编辑内容能保留；不要替换成随页签销毁组件的 `v-if`。`role="tab"`、`aria-selected` 与键盘切换让页签可用键盘操作。表单输入、错误和确认区分别排版，避免按钮挤在一行。

`useUnsavedChanges` 处理当前页面的离开提醒，不把正文写到 localStorage。浏览器关闭提醒的文字由浏览器决定。它不承诺刷新后恢复草稿。

文件拖拽和选择共用一套前端格式/大小校验；后端仍负责真正的内容校验。OCR 进行中只显示等待状态，完成后保存为草稿。发布前需要保存修改并勾选人工核对。

完整源码以 [逐文件代码与讲解](13-逐文件代码与讲解.md) 最后的“界面优化最终文件”章节为准。

## 跟写顺序

1. 新建 `src/styles/extensions.css`，在 `main.ts` 的原样式导入之后导入，复用工作台的颜色变量。
2. 新建 `composables/useUnsavedChanges.ts`。`onBeforeRouteLeave` 是 Vue Router 提供的离开钩子，`beforeunload` 是浏览器关闭/刷新的事件；自定函数名可以一起改。
3. 替换最终 BasicAnalysisPanel，保留原查询、重做和人工采用接口，换成摘要卡片。
4. 替换 EmailPanel，再改 TicketDetailView 的页签和带入邮件事件。`v-show` 保留内存草稿，关闭页面仍可能丢失。
5. 替换 KnowledgeEditor。保存成功后更新 savedSnapshot，表示当前内容已经保存；有未保存修改时禁用发布按钮，避免把旧正文发布出去。
6. 更新 AssistancePanel 的页签提示文字；运行 `npm run typecheck`、`npm run build`，再按下述清单操作。

标题、配色、间距和按钮文案可以改；`request_id`、结果状态、人工确认字段和文件限制要与后端一致。拖拽只是输入方式，不能代替后端校验。共享离开提醒只服务邮件和知识编辑页，工单原有备注和 AI 建议输入仍按原流程保存。

## 浏览器验收

- 点击页签或用左右方向键切换，Home/End 跳到首尾；邮件输入在切换后保留。
- 邮件未勾确认不能发送；明确校验失败后可继续编辑；接受后锁定原请求，结果不确定时只核查原请求。
- 新增知识可选择/拖拽文件，移除后清空选择；识别返回正文后先校对保存。未保存或未勾人工核对时，发布按钮不可用。
- 有邮件或知识编辑未保存时尝试离开，取消应留在原页面；切换工单页签不弹离开提醒。
- 390 像素窄屏下页头按钮能完整显示，检索参考区用按钮打开，Esc 可关闭并把焦点还给按钮。

本轮仅修改最终前端及教程，不新增依赖、后端接口或数据库迁移。

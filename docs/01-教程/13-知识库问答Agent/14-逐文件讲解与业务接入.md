# 逐文件讲解与业务接入

## 1. qa_graph.py：先把流程看懂

| 代码 | 大白话 | 固定还是可改 |
|---|---|---|
| BaseModel、Field | 检查外部输入和模型输出 | 库 API 固定；字段、长度是业务约定 |
| Question | 本轮问题、产品范围、最近消息 | 项目类型；不要接受客户端任意历史 |
| Source | 一条能定位到原文的依据 | 字段可扩展，来源 ID 必须与检索一致 |
| Plan / Assessment | 模型提出下一步建议 | action 取值要与路由判断一起修改 |
| State | 一轮执行共用的工作记录 | 项目字段；不等同于数据库 |
| resolved_question / query | 前者保留理解后的完整问题，后者是可改写的检索词 | 两者不能合并，否则补查可能丢失追问含义 |
| StateGraph | 根据状态组织流程 | LangGraph 固定接口 |
| add_node / add_edge | 登记步骤、连接步骤 | 方法名固定，节点名自己起 |
| add_conditional_edges | 按结果决定下一步 | 固定接口，分支条件是业务规则 |
| compile / ainvoke | 整理流程、异步运行流程 | 固定接口 |
| searches < 2 | 最多再查一次 | 本教程的预算规则，可评测后调整 |
| recursion_limit | 防止图无限执行的额外上限 | 框架配置；不能代替业务次数限制 |

`plan` 负责理解问题，`retrieve` 负责查，`assess` 负责判断资料，`generate` 负责回答。一项一步，不把数据库、页面和模型调用都堆进同一函数。

## 2. 两个接入函数要遵守的契约

核心流程通过 `build_graph(model, search)` 接入业务，测试用替身，正式环境用真实函数。

### model(instruction, data, result_type)

返回 result_type 对应的 Pydantic 对象。可以继续使用第七部分 ChatClient；它负责连接超时、禁用无依据重试、JSON 解析与资源关闭。

下面是可放入 `qa/adapters.py` 的模型适配函数。chat 是由现有依赖提供的 ChatClient；其生命周期应包住整次问答，不能在任务未完成时关闭。

```python
import asyncio

def model_adapter(chat):
    async def call(instruction, data, result_type):
        return await asyncio.to_thread(chat.ask, instruction, data, result_type)
    return call
```

`asyncio.to_thread` 使用运行时线程池执行已有同步 SDK，不需要自己创建 ThreadPoolExecutor。传入的是数据，不把 AsyncSession 交到工作线程里。取消等待不会立即杀死线程里的 SDK，因此保留原模型的网络超时。

### search(query, product_id)

返回 `list[Source]`，最多 5 条、来源 ID 唯一；查询条件必须限定传入产品。空列表只表示正常查询后没有有效资料，连接错误、索引未就绪要继续抛出明确异常。

正式工程把按文本检索写在 `qa/adapters.py`，直接复用原 EmbeddingClient、KnowledgeIndex、发布状态与指纹校验。原工单入口继续自己生成 query 和检索范围，不伪造一个临时工单对象来绕过参数。

处理顺序：

1. 对 query 生成向量；向量模型和索引元数据保持一致。
2. 用 `product_id == 数字` 作为 Milvus 过滤条件。数字来自已校验的会话，不能将用户文本拼进过滤表达式。
3. 混合检索后，按 chunk_id 回到 PostgreSQL 查询 KnowledgeChunk 和 KnowledgeDocument。
4. 丢弃文档不存在、不是 published、产品不一致、指纹过期的命中。
5. 按排名返回最多 5 条 Source；`source_id` 用 `K{chunk.id}`，标题、正文、指纹来自数据库。

不要照搬“同模块不够就扩大到同分类”到自由问答中，避免跨产品回答。索引与业务记录过滤要同时正确。当前实现若索引命中却全部属于已停用或已变更资料，会提示重建知识索引；真正没有命中时才进入“依据不足”分支。

## 3. service.py：数据库会话与耗时操作

服务函数使用 `AsyncSession`；`await db.get/execute/scalar/scalars/commit/refresh`。`db.add` 不加 await；`(await db.scalars(query)).all()` 中 all 是内存结果读取，也不加 await。

短事务准备消息后释放连接；模型等待前把所需记录转为普通值。独立检索步骤用自己的短会话，不在多个并发节点之间共享 AsyncSession。第一版节点按顺序运行。

当前实现从最近消息中取最多 6 个完整问答对，总历史正文不超过 6000 字符。它是避免无限增长的工程上限，不能当成精确 token 预算；你换模型后要按该模型上下文窗口实测。超长历史从较旧的消息对移除，不伪造摘要替代原话。

历史引用用于展示快照；本轮必须重新检索。返回回答前复核当前资料，已停用或版本已变化时，先在独立短事务将本轮 running 置为 failed，再返回 409，请用户重新生成，不能保存成最新有效依据。未知异常和请求取消也必须完成相同状态收尾，然后重新抛出，确保会话可以继续提问。

## 4. router.py：在边界做检查

使用已有 CurrentUser、DbSession 依赖；通过 `owner_id == user.id` 查会话。不存在或不属于当前用户统一返回 404；不要先返回其他用户的消息再让页面隐藏。

错误约定：422 输入不合格；409 同会话忙、重复请求正文变化或引用失效；502 模型/Embedding 上游失败；503 索引未准备好或配置缺失；504 本轮超过明确的时间预算。沿用项目错误响应和 request_id，不向用户暴露密钥或数据库连接串。

## 5. 前端三个位置

`api/qa.ts`：复用现有请求工具和 Zod 响应校验，添加四个问答接口；路径传 `/qa/...`，因为请求工具已经加了 `/api`。

`KnowledgeChatView.vue`：左侧会话列表，主区消息和输入框，回答下方列来源。用户发送后先显示自己的消息和等待状态；失败显示可读错误，输入内容保留。刷新先读历史，发现 running 后每 2 秒读取一次最新消息页；上一请求结束后才安排下一次。进入终态、切换会话、组件卸载或读取失败时停止轮询；读取失败显示错误和手动刷新按钮。读取历史不会再次调用模型。

`router/index.ts` 和 `AppSidebar.vue`：添加 `/qa` 页面入口“智能助手”，位于“工单管理”上方，沿用登录保护。正文和引用按普通文本渲染；如另加 Markdown 渲染库，必须处理 HTML 安全，不能把模型输出直接塞进 v-html。

现有 `frontend/src/api/http.ts` 已支持可选 `timeoutMs`，普通请求仍为 10 秒；问答发送使用 160 秒，后端单轮预算 150 秒。不要整体延长登录等普通请求的超时。

## 6. 正式工程逐文件看什么

| 文件 | 大白话 | 固定写法 / 可改内容 |
|---|---|---|
| `qa/graph.py` | 一轮问答的流程图：理解问题、检索、判断、回答 | LangGraph 的 `StateGraph`、`add_node`、`compile` 是固定 API；提示词和最多补查一次是业务规则 |
| `qa/adapters.py` | 给流程图接上已有聊天模型和知识索引 | `asyncio.to_thread` 是同步 SDK 在异步接口中的接法；来源数量与产品范围是本项目规则 |
| `qa/schemas.py` | 检查页面传来的产品、标题、正文、请求编号 | `BaseModel`、`Field` 是 Pydantic API；字段长度可按业务调整，但前后端要同步 |
| `qa/service.py` | 保存会话和消息、处理重复请求、失败与来源复核 | `async with session_factory.begin()` 是数据库事务写法；错误文案和超时预算可按验收结果调整 |
| `qa/router.py` | 把四个 URL 接到服务函数，并限定为当前登录用户 | `APIRouter`、`Depends` 是 FastAPI API；路径与返回结构是本项目前后端约定 |
| `frontend/src/api/qa.ts` | 页面统一从这里调用四个接口并校验返回 | `request` 与 Zod 是项目已有写法；字段名必须与后端契约一致 |
| `frontend/src/views/KnowledgeChatView.vue` | 会话列表、输入框、回答、来源和刷新恢复 | Vue 的 `ref`、`computed` 是固定写法；文案与布局可改，不能扩大知识检索范围 |

先读 `graph.py` 的 `plan → retrieve → assess → generate`，再从 `router.py` 的 `send` 顺着 `service.py` 往下找。`Question.history` 来自数据库，页面不能自带历史；`product_id` 来自会话，模型只能改写查询词。保存的来源是当时的快照，点开文档时仍会按当前发布状态检查权限。

## 7. test_qa_graph.py：测试究竟证明了什么

8 项测试覆盖：合法引用、追问不查库、最多两次检索、空结果不能凭空回答、伪造来源拒绝、检索故障不当空结果、历史消息传给规划节点，以及多轮追问改写检索词后仍保留完整问题并成功回答。

这些测试实际执行 LangGraph，但模型和检索内容由测试提供。数据库归属、事务并发、版本复核、网页和真实回答质量要按下一页验收，不能拿模拟响应冒充远程模型效果。

# 客户与客服双端实施计划

目标：按照已确认的蓝白设计图，让客户咨询、转人工，客服接单和转交；模拟客户与三级客服。

## 账号与权限

- [x] users 增加 customer 身份、客户等级、客服等级；数据库迁移保留现有账号。
- [x] 区分登录身份与客服接口权限；客户不得读取内部工单、账号列表和内部知识问答。
- [x] 生成四个客户和 L1/L2/L3 客服账号，凭据只保存至被 Git 忽略的本地文件。

## 服务闭环

- [x] 客户拥有独立咨询入口，按身份限制对话与工单归属。
- [x] 转人工关联对话与工单；排队期间提示真实状态，人工接入后停止自动回复。
- [x] 工单按严重程度、客户等级、等待时间排序；原子接单避免重复领取。
- [x] 申请换人保留原工单与消息，记录转交原因及处理级别。
- [x] 客服回复、提交解决结果，客户确认或申请继续处理。

## 页面与验证

- [x] 客户端：咨询、我的工单、产品及演示服务守则。
- [x] 客服端：待接、处理中列表和分级信息；转交后进入待接列表。
- [x] 登录后按身份跳转，路由与后端权限一致。
- [x] 验证客户之间隔离、客户不可访问内部接口、接单和转交状态、排序、模型失败。
- [x] 执行后端相关测试、前端 typecheck/build、真实浏览器联调。

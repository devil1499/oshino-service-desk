# 智能助手运行记录与回答评测

## 本次范围

按已确认方案实施客服端：回答下显示耗时和 Token，运行详情展示步骤、模型调用、上下文和知识快照；管理中心增加独立回答评测。不增加赞踩反馈，不修改客户咨询流程。

## 实现安排

1. 先用模拟 HTTP 检查真实 usage 采集：多次调用累加、缺失为未知、JSON 校验失败保留已返回用量、并发隔离。
2. 在 LangGraph 节点开始和结束保存步骤，独立记录 Chat 与 Embedding。新增迁移 15，旧回答 run_details 为 NULL，不补造记录。
3. 每个会话仅所有者能读取详情。保存规则脱敏后的提示、历史消息、模型输入、解析输出、检索资料和最终引用。鉴权头和服务密钥不进入记录。
4. UI 对完整与部分 Token 采用不同文案；耗时未知不填 0。服务中断保留已完成步骤并明确标注不完整。
5. 固定题集与知识版本绑定，评测运行与日常会话分离。先执行问答，再人工分维度评分，缺失评分不计 0，不把运行成功率作为回答准确率。
6. 验证单元测试、隔离 PostgreSQL 集成测试、前端构建和浏览器操作；真实模型少量联调，固定题集不未经检查自动跑满。

## 记录口径

- 总耗时从准备本轮问答开始，到保存最终回答前为止；包含历史读取、流程执行、引用核验和记录检查点。步骤耗时不包括结束检查点落库，故步骤合计不一定等于总耗时。
- Token 来自接口的 usage，包含计划、依据判断、生成，以及再次检索后的模型调用。JSON 解析失败但收到 usage 的调用也计入。Chat 和 Embedding 分开统计。
- “完整”表示所有已知调用的该类用量字段齐全；上游失败没有 usage 时为部分统计。未调用时为 0，已调用但未返回时为未知。
- 重启中断的整轮耗时未知，保留已保存的节点和用量，整轮统计标为不完整。历史回答不会追溯补出 Token。
- 规则脱敏覆盖邮箱、手机号、显式密码/验证码/API Key/Token 字段和常见凭据格式，不等于能识别任意自然语言个人信息。请不要把隐私或密钥写进问题和知识文档。
- 运行详情是应用的输入、输出与执行步骤，不是模型内部思维链。知识版本用文档指纹标识；后续知识更改不会覆盖本轮快照。

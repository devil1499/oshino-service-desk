# AI 服务与联网搜索实施计划

已确认：独立 DeepSeek Search API 加现有聊天接口，不更换为 Responses API。不使用子代理，不提交推送。

## 设计与文件

管理员在管理中心的“AI 服务”设置聊天地址、模型、密钥与联网搜索开关、独立或复用密钥。只返回密钥是否配置；留空保留原密钥。配置存入项目 `.local/ai-service/settings.json`，Docker 单独挂载该私有目录，原 `.env.chat` 保持只读；未保存时沿用原聊天配置。格式错误直接报错，不静默忽略。

- `core/ai_settings.py`：配置读取、校验、原子保存；`modules/ai_service.py`：管理员读写、连接测试，客服只读能力开关。
- `integrations/web_search.py`：DeepSeek 官方搜索接口，校验结果和 HTTP(S) 来源，超时 20 秒、不自动重试；不自行访问结果网址。
- QA graph/adapters/service：开启后先检索当前产品知识，再查网络；模型只能引用提供的 K/W 来源。知识库无结果不等于网络成功；网络故障保存准确失败状态，不回退伪装成功。
- `WebSource` 与知识来源使用不同字段，记录网页链接、标题、摘要、抓取时间，网页是参考，不能覆盖产品内部政策。引用快照不自动导入知识库。
- `AiServiceView.vue`：两个配置区域、保存和独立连接测试；`KnowledgeChatView.vue`：本轮联网开关、来源展示；运行详情显示搜索步骤与请求次数，不编造搜索 Token。
- 消息增加 `web_search` 字段与迁移 16，确保幂等重试不能改变搜索模式。客户端和固定评测不启用联网。

## 按顺序验证

1. 先写配置公开接口测试，覆盖管理员权限、密钥不返回、留空保留、配置不完整报错；实现保存与即时读取。
2. 搜索 HTTP 边界测试先失败，再实现真实契约、超时/401/402/429 和非法网址拒绝。
3. graph 测试验证开关、外部来源引用、伪造引用拒绝；数据库测试验证联网结果落库、失败落库、同请求不同模式冲突。
4. 前端导航测试，类型检查、构建；浏览器验证表单、来源、开关与记录。真实接口只执行少量验收查询，不发送客户私人信息，固定题集不自动跑满。

参考：DeepSeek 官方 https://api-docs.deepseek.com/api/search/ 与 https://api-docs.deepseek.com/guides/search/ ，2026-11-04 核验。使用 `/v1/tools/search`，query 最多 128 字，count=5，need_content=false，基于返回的 summary 回答。

## 使用步骤

1. 管理员打开“管理中心 → AI 服务”（`/admin/ai-service`）。首次打开会读取原 `.env.chat` 的地址、模型和密钥配置状态，已保存的密钥不会回传。
2. 编辑聊天地址、模型和密钥，启用 DeepSeek 搜索；聊天本来使用 DeepSeek 官方密钥时可复用，其他兼容平台的密钥须另填官方搜索 Key。密钥输入留空保留已有值。先保存，再点击独立连接测试；测试会调用真实服务。
3. 保存后以 `.local/ai-service/settings.json` 为准，新的问答、工单分析与建议即时读取，无需重启。Docker 已挂载这个私有目录；该目录和密码文件由 Git 忽略。文件以本机私有配置形式保存，未采用数据库加密；备份时按凭据文件保管，不加入仓库或公开教程。
4. 客服在“智能助手”每轮提问时勾选“联网搜索”；默认关闭。回答中的 K 为当前产品的知识库依据，W 为本轮网页参考，展开查看标题、链接、摘要和检索时间。网络资料不会自动发布到知识库。
5. “运行详情”展示搜索步骤、实际发送的脱敏查询、网页结果快照和耗时。搜索尝试次数独立显示，不把它当作 Token；聊天与 Embedding 仍分别统计接口真实 usage。搜索故障会失败并展示原因，不静默改成无依据回答。
6. 固定评测题与客户咨询不启用联网。人工比较答案时分别核对内部政策与网络事实；一次真实问答成功不代表所有网页内容均正确。

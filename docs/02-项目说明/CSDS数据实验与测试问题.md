# CSDS 数据实验与测试问题

这份数据用于本机实验，不是系统已有工单或正式知识库内容。原始文件在 `C:\Users\cheng\CSDS`，转换结果在项目的 `data/evaluation/csds/`。转换只读原始文件，不修改它们。生成目录已在 `.gitignore` 中排除；换电脑后需要带上原始数据重新转换。

## 数据放在哪里、各文件做什么

`train`、`val`、`test` 各有一套同名文件：

| 文件 | 用途 |
| --- | --- |
| `documents.jsonl` | 一段客服对话是一篇实验文档，保留每轮发言及其位置。 |
| `chunks-fixed-500-80.jsonl` | 模仿项目当前的固定 500 字、重叠 80 字切分。 |
| `chunks-dialogue-turns.jsonl` | 尽量按完整对话轮次切分；超长发言仍需拆开。 |
| `queries.jsonl` | 检索输入，只有问题，不含参考答复。 |
| `answers.jsonl` | 参考答复及其对应的对话轮次，只供评测。 |
| `analysis.jsonl` | 自动分析输入与参考问题摘要；原数据没有项目的分类 ID 和 P1–P4 优先级，所以这两项是 `null`。 |

原始数据共转换出训练集 9,101 段对话、18,018 条分析样本；验证集 800 段对话、1,591 条分析样本；测试集 800 段对话、1,517 条分析样本。有参考答复轮次的检索问题分别为 17,946、1,587、1,515 条。训练集用于开发，验证集用于比较方案，测试集留到最终检查；不要用测试集反复调参数。

完整的 CSDS 原始对话和离线评测文件没有导入 PostgreSQL 或 Milvus。当前只把训练集筛出的 200 条客服问答摘要作为**独立演示产品**导入本机知识库并重建索引。用智能助手询问这 200 条可检查演示检索；要比较完整语料的切分策略，仍应运行下述离线评测，不能把演示问答命中率当作全数据集指标。

这 200 条的 Markdown 副本放在项目的 `.local/knowledge/csds-qa-200/`。目录内 `README.md` 说明筛选范围和本机导入状态，`manifest.json` 记录原对话编号。知识库中的产品是“CSDS 电商客服演示”，现有 4 篇演示协作平台文档未修改。原数据没有“已办结”标记，不能把客服答复摘要称为已解决工单。验证集、测试集未用于这批演示问答，仍可用于离线评测。数据来源为 [CSDS 官方项目](https://github.com/xiaolinAndy/CSDS)。

## 如何运行

在 WSL 中从项目根目录执行：

```bash
cd /mnt/e/oshino
python3 scripts/convert_csds.py --source /mnt/c/Users/cheng/CSDS --output data/evaluation/csds
python3 scripts/evaluate_csds_chunks.py --dataset data/evaluation/csds/val
python3 scripts/evaluate_csds_retrieval.py --dataset data/evaluation/csds/val --top-k 5
python3 -m unittest discover -s scripts -p 'test_csds_conversion.py'
```

第一条是重新生成数据，已有转换结果时不用重复运行。后两条评测命令不需启动数据库、模型或前端。

切分报告中的 `evidence_available_rate` 表示参考答复的每个标注轮次，能否在至少一个片段中完整找到；`single_chunk_evidence_rate` 表示同一问题的全部标注轮次能否放进同一片段。这是**证据覆盖情况**，不是检索召回率。

检索报告用字符二元组 BM25 排序，`hit_at_5` 表示前 5 个片段至少一个完整命中参考轮次，`evidence_recall_at_5` 表示前 5 个片段覆盖了多少标注轮次，`full_answer_at_5` 表示全部标注轮次均被覆盖，`mrr_at_5` 考虑首个命中的排名。命中必须来自正确的原始对话。这些指标只验证**本地词面检索基线**；不能代表现有 Embedding、Milvus、AI 自动分析或最终答复的效果。

本机验证集结果（2026-10-31）：

| 切分方式 | 证据可完整覆盖 | 同片段包含全部证据 | 词面检索 Hit@5 | 词面检索证据 Recall@5 |
| --- | ---: | ---: | ---: | ---: |
| 固定 500 字、重叠 80 字 | 99.56% | 94.90% | 79.58% | 78.43% |
| 对话轮次切分 | 100.00% | 92.63% | 78.32% | 76.64% |

这里两种方式各有得失，不能只看一个数决定正式知识库如何切分。CSDS 是客服对话；项目知识库还有产品说明等文档，它们的结构不同。

## 手工测试：自动分析

这部分先作为人工测试题。当前项目的页面入口是工单详情中的“AI 处理建议 → 生成处理建议”，并没有独立的 CSDS 批量自动分析评测入口。要试页面，可以把“输入原话”填到新建的**测试工单**的问题描述中，在模型与检索来源配置可用时生成建议，只核对其中的**问题摘要是否保留关键事实**。现有知识库不是 CSDS，不能把整个建议是否正确归因于这批数据。下面“参考摘要”是数据集标注，不是必须逐字一致的标准答案。原数据没有项目优先级和分类标签，不能凭这张表给分类或优先级打分。

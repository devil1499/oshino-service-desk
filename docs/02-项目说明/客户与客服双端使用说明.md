## 验收顺序

1. 客户登录，在“服务咨询”选择产品，填写问题简述并开始咨询。发送“耳机无法连接手机，怎么排查？”可测试真实模型回答和知识来源。
2. 输入“转人工”或点击转人工按钮，填写现象、已尝试步骤与问题严重程度。提交后产生待接工单，AI 不再回复此会话。
3. 小林登录“服务工作台”，点击刷新，打开待接工单并接入。客服可以查看转人工前的 AI 对话，核定优先级、回复客户。
4. 客户说明不满意原因并申请更换客服。同一个工单回到待接队列，消息和处理记录保留；上一位客服不能马上重新领取。小李可以继续接单。
5. 客服可填写原因升级到 L2 或 L3，低于所需等级的客服不能接单。
6. 客服提交处理结果后，客户确认完成；也可以在确认前申请更换客服继续处理。完成后的会话不能继续发送消息。

已准备 5 条“演示：”开头的待接工单，以及一条完整走过 AI、转人工、更换客服、确认完成的“演示验收：”会话。它们都是真实写入本机数据库的虚构演示记录。

## 排序与权限

- 严重程度：P1 严重风险或大范围故障；P2 核心功能无法使用；P3 部分功能异常；P4 普通咨询。
- 相同优先级：最强王者 → 王者 → 铂金 → 青铜；相同等级再按工单创建时间从早到晚排序。
- 客户初报严重程度，接单客服核实。客户等级不是 P1～P4 的代替品。
- 客户只能访问自己的咨询，无法访问内部工单、人员管理、知识编辑和客服智能助手接口。
- 客服只能在转人工后读取该客户服务会话；回复和处理限当前接单人或管理员。
- 接单使用数据库行锁，并发领取只能成功一次。重复转人工返回同一工单。
- 旧“全部工单”仍可查询客户工单，但修改、处理应回到“服务工作台”，防止绕过客户确认流程。

## 页面和实现位置

| 文件 | 作用 |
|---|---|
| frontend/src/views/ServicePortalView.vue | 客户咨询、客服队列、消息、转交和处理结果 |
| frontend/src/views/ServiceInfoView.vue | 产品、人员等级和模拟守则 |
| frontend/src/api/service.ts | 服务会话请求和返回数据校验 |
| backend/app/modules/service_portal.py | 身份、归属、接单、转交和会话接口 |
| backend/app/seed_service.py | 创建演示账号、产品及两份知识资料 |
| backend/migrations/versions/14_customer_service.py | 客户身份、等级、工单归属与对话关联 |
| backend/tests/test_service_portal.py | 隔离测试库中的服务闭环、排序和并发接单检查 |

会话打开时每 4 秒读取进度，不使用 WebSocket；读取失败显示错误，可手动“重新连接”。队列每页 50 条，页面筛选、搜索和数量卡片只统计当前页，按钮已明确标注。模型失败会显示准确错误；转人工受理不依赖模型正常返回。

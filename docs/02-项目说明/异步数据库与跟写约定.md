# 异步数据库与正式工程跟写约定

这页解决“教程代码如何接到当前正式工程”，应在第二部分和之后每次新增后台任务前阅读。检查对象是 `E:\oshino` 的 `XM` 分支；本文给出可跟写的接线代码，不表示已经把后续业务接入正式后端。

## 1. 先分清两种代码的位置

旧教程的完整参考源码已经改成 `AsyncSession`，但其中的 `engine`、`SessionFactory` 和 `settings` 仍是独立教学工程的模块级对象。当前正式工程通过 `create_app()` 的 lifespan 创建配置、密码服务和数据库，把它们放进 `app.state`。两边都异步，不代表能把基础文件互相覆盖。

**在当前正式工程跟写，以这页的接线为准：保留 `create_app`、`Settings.load()`、`PasswordService`、现有错误处理和 request_id 中间件；业务路由继续用正式的 `DbSession`、`CurrentUser`、`AdminUser`。** 不额外创建另一套全局连接池。新增模型、字段和迁移仍需要按阶段与现有模型核对，这页只处理配置与会话的接入，不承诺任意旧源码整文件覆盖后全业务兼容。

正式 `app/seed.py` 已自行创建异步 engine、调用 `PasswordService` 并在 finally 释放连接，初始化管理员时保留它，不复制参考工程依赖全局工厂的 seed。正式 `security.py`、`settings.py`、用户路由也保留现有实现；后续章节新增的是业务能力，不重新安装另一套登录基础。

| 旧参考中的名字 | 正式工程的来源 |
|---|---|
| `settings` 全局变量 | 路由注入 `AppSettings`；命令执行时 `Settings.load()` |
| `password_hash` 全局对象 | 路由注入 `Passwords`，调用 `await passwords.hash/verify` |
| `engine` 全局变量 | lifespan 内部的 engine；命令自己创建并释放 |
| `SessionFactory` 全局变量 | 请求注入 `SessionFactoryDep`；后台函数显式接收 factory |
| `create_access_token(user_id)` | 正式签名为 `create_access_token(user_id, settings)` |

## 2. 数据库依赖：保留正式连接设置，新增“拿工厂”的入口

下面是当前正式 `backend/app/core/database.py` 的完整替换内容；连接超时、UTC、SQL 超时和连接池设置都沿用正式文件，只把取工厂抽成函数并增加依赖别名：

```python
from collections.abc import AsyncIterator
from typing import Annotated, cast

from fastapi import Depends, Request
from pydantic import SecretStr
from sqlalchemy.ext.asyncio import AsyncEngine, AsyncSession, async_sessionmaker, create_async_engine
from sqlalchemy.orm import DeclarativeBase


class Base(DeclarativeBase):
    pass


def create_database_engine(database_url: SecretStr) -> AsyncEngine:
    return create_async_engine(
        database_url.get_secret_value(),
        connect_args={"connect_timeout": 5, "options": "-c timezone=UTC -c statement_timeout=10000"},
        hide_parameters=True,
        pool_size=5,
        max_overflow=5,
        pool_timeout=5,
    )


def get_session_factory(request: Request) -> async_sessionmaker[AsyncSession]:
    return cast(async_sessionmaker[AsyncSession], request.app.state.session_factory)


SessionFactoryDep = Annotated[async_sessionmaker[AsyncSession], Depends(get_session_factory)]


async def get_db(request: Request) -> AsyncIterator[AsyncSession]:
    async with get_session_factory(request)() as session:
        yield session
```

工厂负责“创建一个新会话”；会话负责“本次访问数据库”。路由的 `DbSession` 仍由正式 `get_db` 提供。后台任务不能收到当前请求的会话，应收到工厂并自行开关会话。

`async_sessionmaker`、`Depends`、`async with` 是库或语言写法。`get_session_factory`、`SessionFactoryDep` 是本教程命名，改名需同步调用方。

## 3. 第五、六部分：两个独立重建命令自己管理连接

CLI 没有 HTTP 请求，也没有 `request.app`。所以命令应加载配置、创建异步 engine 和工厂，退出时释放 engine。不能从正式 `database.py` 导入不存在的 `engine, SessionFactory`。

以下两份是对应重建脚本的完整替换；仍需先跟写各自的模型、索引与 Embedding 文件。只在后端停止时执行重建，保留原 `--replace` 规则。它们读取 `Settings.load()`，不会在教程正文写数据库密码。

### 第五部分：backend/app/rebuild_cases.py

```python
import asyncio
import argparse

from sqlalchemy import select

from sqlalchemy.ext.asyncio import async_sessionmaker

from app.core.database import create_database_engine
from app.core.settings import Settings
from app.core.retrieval_settings import RetrievalSettings
from app.integrations.case_index import CaseIndex
from app.integrations.embeddings import EmbeddingClient, EmbeddingError
from app.models import Ticket
from app.modules.analysis.cases import case_row, case_text


async def main() -> None:
    parser = argparse.ArgumentParser(description="后端停止后，全量重建有效历史案例索引")
    parser.add_argument("--replace", action="store_true", help="允许替换已有派生索引，PostgreSQL 工单不变")
    args = parser.parse_args()
    config = RetrievalSettings()
    engine = create_database_engine(Settings.load().database_url)
    session_factory = async_sessionmaker(engine, expire_on_commit=False)
    try:
        async with session_factory() as db:
            async with await asyncio.to_thread(CaseIndex, config.milvus_db_path, config.embedding_model,
                str(config.model_base_url), config.embedding_dimensions) as index:
                if await asyncio.to_thread(index.client.has_collection, "ticket_cases") and not args.replace:
                    raise SystemExit("索引已存在；请停后端并加 --replace 重建")
                tickets = (await db.scalars(select(Ticket).where(
                    Ticket.status.in_(["resolved", "closed"]), Ticket.solution != "",
                ).order_by(Ticket.id))).all()
                await asyncio.to_thread(index.reset)
                async with await asyncio.to_thread(EmbeddingClient, str(config.model_base_url), config.model_api_key.get_secret_value(),
                                     config.embedding_model, config.embedding_dimensions) as model:
                    # 每批 10 条，同时兼容本教程所用接口的请求批量上限。
                    for start in range(0, len(tickets), 10):
                        batch = tickets[start:start + 10]
                        vectors = (await asyncio.to_thread(model.embed, [case_text(ticket) for ticket in batch]))
                        await asyncio.to_thread(index.add, [case_row(ticket, vector) for ticket, vector in zip(batch, vectors, strict=True)])
                        print(f"已写入 {start + len(batch)} / {len(tickets)} 条有效案例", flush=True)
                await asyncio.to_thread(index.finish, len(tickets))
                print(f"索引构建完成：{len(tickets)} 条。可以重新启动后端。")
    except EmbeddingError as error:
        raise SystemExit(f"构建失败：{error}。索引未就绪，修正后重新执行 --replace。") from None
    finally:
        await engine.dispose()


if __name__ == "__main__":
    asyncio.run(main())
```

### 第六部分：backend/app/rebuild_knowledge.py

```python
import asyncio
import argparse

from sqlalchemy import select

from sqlalchemy.ext.asyncio import async_sessionmaker

from app.core.database import create_database_engine
from app.core.settings import Settings
from app.core.retrieval_settings import RetrievalSettings
from app.integrations.embeddings import EmbeddingClient, EmbeddingError
from app.integrations.knowledge_index import KnowledgeIndex

async def main():
    parser = argparse.ArgumentParser(description='停止后端后重建已发布知识索引')
    parser.add_argument('--replace', action='store_true', help='允许替换知识索引，保留业务表和案例索引')
    args = parser.parse_args()
    config = RetrievalSettings()
    engine = create_database_engine(Settings.load().database_url)
    session_factory = async_sessionmaker(engine, expire_on_commit=False)
    try:
        async with session_factory() as db:
            async with await asyncio.to_thread(KnowledgeIndex, config.milvus_db_path, config.embedding_model,
                str(config.model_base_url), config.embedding_dimensions) as index:
                if await asyncio.to_thread(index.client.has_collection, 'knowledge_chunks') and not args.replace:
                    raise SystemExit('知识索引已存在，请停后端后使用 --replace')
                rows = (await db.execute(select(KnowledgeChunk, KnowledgeDocument).join(KnowledgeDocument)
                                  .where(KnowledgeDocument.status == 'published')
                                  .order_by(KnowledgeChunk.id))).all()
                await asyncio.to_thread(index.reset)
                async with await asyncio.to_thread(EmbeddingClient, str(config.model_base_url), config.model_api_key.get_secret_value(),
                                     config.embedding_model, config.embedding_dimensions) as model:
                    for start in range(0, len(rows), 10):
                        batch = rows[start:start + 10]
                        vectors = (await asyncio.to_thread(model.embed, [f'{doc.title}\n{chunk.content}' for chunk, doc in batch]))
                        (await asyncio.to_thread(index.add, [{'chunk_id': chunk.id, 'content': f'{doc.title}\n{chunk.content}',
                                    'dense_vector': vector, 'product_id': doc.product_id,
                                    'module_id': doc.module_id, 'category_id': doc.category_id,
                                    'fingerprint': chunk.fingerprint}
                                   for (chunk, doc), vector in zip(batch, vectors, strict=True)]))
                        print(f'已索引 {start + len(batch)} / {len(rows)} 个知识分块', flush=True)
                await asyncio.to_thread(index.finish, len(rows))
                print('知识索引构建完成，可启动后端')
    except EmbeddingError as error:
        raise SystemExit(f'构建失败：{error}；知识索引未就绪') from None
    finally:
        await engine.dispose()


if __name__ == '__main__':
    asyncio.run(main())
```

```python
async def run_analysis(
    session_factory: async_sessionmaker[AsyncSession], ticket_id: int, attempt: int,
):
    async with session_factory() as db:
        row = (await db.get(BasicAnalysis, ticket_id))
        if row.attempt != attempt or row.status != "pending":
            return
        ticket = (await db.get(Ticket, ticket_id))
        categories = [
            {"id": c.id, "name": c.name}
            for c in (await db.scalars(select(TicketCategory).where(TicketCategory.is_active))).all()
        ]
        data = {"title": ticket.title, "description": ticket.description, "categories": categories}
        row.status = "running"
        await db.commit()
    result = None
    model_name = None
    error_message = None
    try:
        config = BasicModelSettings()
        model_name = config.chat_model
        async with await asyncio.to_thread(ChatClient,
            str(config.model_base_url), config.model_api_key.get_secret_value(), config.chat_model
        ) as chat:
            result = (await asyncio.to_thread(chat.ask,
                "概括工单，从给出的启用分类中选择category_id，建议P1至P4优先级并解释原因。",
                data,
                BasicResult,
            ))
        if result.category_id not in {c["id"] for c in categories}:
            raise ChatError("模型返回了不属于启用分类的 ID")
    except ValidationError:
        error_message = "模型配置缺失或无效，请检查 .env.retrieval 和 .env.chat"
    except ChatError as error:
        error_message = str(error)
    async with session_factory.begin() as db:
        row = (await db.get(BasicAnalysis, ticket_id))
        if row.attempt != attempt:
            return
        row.model = model_name
        row.updated_at = datetime.now(timezone.utc)
        ticket = (await db.get(Ticket, ticket_id))
        if fingerprint(ticket) != row.fingerprint:
            error_message = "分析期间工单内容已变化，请重新分析"
        row.status = "failed" if error_message else "completed"

```

`run_analysis` 的两个数据库阶段分别打开自己的会话。模型请求在中间运行，`AsyncSession` 不进入工作线程。业务判断保持原样。

同文件中保留原 `@router.post("/{ticket_id}/analysis", status_code=202)` 装饰器，将 `retry_analysis` 函数替换为：

```python
async def retry_analysis(ticket_id: int, db: DbSession, user: CurrentUser, background: BackgroundTasks,

    row = (await queue_analysis(db, ticket))
    await db.commit()

```

创建工单后也会安排分析，不能只改“重新分析”入口。第十部分 `backend/app/modules/tickets/router.py` 新增 `from app.core.database import SessionFactoryDep`；保留原 POST 装饰器，`create_ticket` 函数替换为：

```python
async def create_ticket(body: TicketCreate, db: DbSession, user: CurrentUser, background: BackgroundTasks,
                        session_factory: SessionFactoryDep):
```

## 6. main.py：恢复放在 lifespan 内，保留 create_app

按阶段新增路由时，在正式 `create_app` 内保留已有 `app = FastAPI(...)`、中间件、`install_error_handlers(app)` 和原路由注册，只加入新增模块的 `app.include_router(...)`。不要复制旧完整参考的顶层 `app = FastAPI(...)` 覆盖本文件。

完成第十部分模型和迁移后，main.py 增加 `from app.modules.analysis.basic import interrupt_analyses`；完成第十一部分后再增加 `from app.modules.email.router import interrupt_deliveries`。在 `create_app` 内用下面内容替换现有 lifespan（保留外部 create_app 的 `settings` 参数）：

```python
@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncIterator[None]:
    config = settings if settings is not None else Settings.load()
    app.state.settings = config
    engine = create_database_engine(config.database_url)
    app.state.session_factory = async_sessionmaker(engine, expire_on_commit=False)
    app.state.passwords = PasswordService()
    try:
        await interrupt_analyses(app.state.session_factory)
        await interrupt_deliveries(app.state.session_factory)
        yield
    finally:
        await engine.dispose()
```

这段函数整体缩进到 `create_app` 内。第二至第九部分没有分析/邮件表，不添加两个 `interrupt_*` 导入与调用；第十部分只添加 `interrupt_analyses`，第十一部分才加邮件恢复。先运行对应迁移再启动。即使恢复步骤失败，finally 仍会释放 engine。

本恢复规则只适用于教程的单工作进程。多个 worker 启动时不能互相把对方任务标记中断；本次不引入多 worker。数据库连接超时和 SQL 超时继续使用正式 `create_database_engine` 的配置。

## 7. async 的常见写法和测试边界

| 操作 | 正式写法 |
|---|---|
| 查一条 | `await db.get(Model, id)` |
| 查集合 | `(await db.scalars(query)).all()` |
| 执行语句 | `await db.execute(statement)` |
| 提交、刷新、回滚 | `await db.commit()`、`await db.refresh(row)`、`await db.rollback()` |
| 放入待保存对象 | `db.add(row)`、`db.add_all(rows)`，不加 await |
| 新事务 | `async with session_factory.begin() as db:` |
| 同步模型、SMTP、索引 SDK | `await asyncio.to_thread(sync_call, 普通参数)` |
| 密码计算 | 注入正式 `Passwords`，`await passwords.hash/verify(...)` |

`AsyncSession` 不能跨并发任务共享，也不能塞进 `to_thread`。更换为 async def 不会让内部同步 SDK 自动异步。已有模型和索引类的 async 上下文管理器负责线程中的关闭；不能漏掉关闭，也不能在任务结束前提前关闭。

参考测试 fixture 中的同步 `create_engine` / `Session` 可用于单独建立测试表、准备与检查数据：它们在测试进程中完成，不能注入异步业务作为 `DbSession`。请求依赖应使用异步工厂，和 TestClient 的应用生命周期一起管理；直接调用 async 函数的测试必须 await，不能只得到协程对象就断言成功。

接入本页后，旧测试里直接调用 `run_analysis(ticket_id, attempt)` 要改成 `await run_analysis(session_factory, ticket_id, attempt)`；恢复函数测试也要传工厂。依赖覆盖要覆盖正式 `get_db` 或应用工厂，不能只替换一个业务已不再读取的全局变量。保留测试数据库隔离，不使用真实业务库。

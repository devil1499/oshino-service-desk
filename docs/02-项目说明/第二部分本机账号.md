# 第二部分本机账号（可共享版）

本文件对应本机私密记录 `.local/第二部分本机账号.md`，保留账号用途、配置位置和初始化方法，供远程仓库查看。实际密码以占位说明替代，不能直接拿占位内容登录。

## 网页管理员

- 本机登录地址：<http://127.0.0.1:18734/login>。
- 用户名：`admin`。
- 初始登录密码：本机随机生成，见当前电脑的 `.local/第二部分本机账号.md`。
- 显示姓名：管理员。
- 用途：登录网页，创建客服，维护产品、模块和问题分类。

网页不包含公共默认密码。数据库只保存密码的 Argon2id 哈希，无法从哈希还原原密码。

## 业务数据库

| 配置项 | 本机设置 |
|---|---|
| 服务位置 | WSL Ubuntu-22.04 的 PostgreSQL |
| 主机 | `127.0.0.1` |
| 端口 | `5432` |
| 数据库名 | `after_sales` |
| 数据库用户名 | `after_sales` |
| 数据库密码 | 本机独立随机密码，见私密记录或 `backend/.env` |
| 后端配置项 | `backend/.env` 中的 `DATABASE_URL` |

连接地址格式如下，密码含特殊字符时需要 URL 编码；`app.configure` 会负责编码：

```text
postgresql+psycopg://after_sales:<URL编码后的数据库密码>@127.0.0.1:5432/after_sales
```

数据库密码供程序连接 PostgreSQL 使用，与网页管理员密码不同。业务数据库用户没有创建数据库的权限。

## JWT 签名密钥

`JWT_SECRET` 只保存在 `backend/.env`，用于给登录令牌签名，不是网页登录密码。配置生成工具会随机生成该密钥；修改并重启后端后，旧令牌会失效，需要重新登录。

## 换电脑后怎样准备账号

克隆仓库不会带回原电脑的数据库、账号、实际密码或 `.env` 文件。新电脑需要先准备 PostgreSQL 角色及数据库，再在 WSL 中安装依赖、生成配置、迁移并创建管理员。

以下路径对应本项目当前位置，换电脑时按实际项目目录调整：

```bash
cd /mnt/e/oshino
source /mnt/e/xiangmu/.venv/bin/activate
cd backend
python -m pip install -r requirements-dev.txt
python -m app.configure
python -m alembic upgrade head
python -m app.seed --username admin --display-name 管理员
```

- `app.configure` 提示输入数据库密码，并生成随机 JWT 签名密钥；已有 `.env` 时拒绝覆盖。
- `app.seed` 提示输入并确认新的管理员密码；已有同名账号时拒绝覆盖。
- `python -m app.configure --test` 为已准备好的测试账号与测试库生成独立配置。
- 网页管理员与客服密码要求 8～128 位；管理员初始化命令和客服创建接口会执行校验。

本阶段尚无密码修改或找回页面。忘记管理员密码时，可以用初始化命令创建不同用户名的新管理员。数据库用户密码由 PostgreSQL 管理，修改后需同步更新本机连接配置。

`.local/`、`.env`、`.env.test` 继续由 `.gitignore` 排除。本机私密记录不会随着密码修改自动更新，应自行同步保管。

表关系、字段约束、数据库角色准备及运行方式见：[第二部分实现与使用说明](第二部分实现与使用说明.md)。

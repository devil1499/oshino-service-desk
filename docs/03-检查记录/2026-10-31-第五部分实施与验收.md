## 配置与运行

本地 `backend/.env.retrieval` 已配置为 Windows Ollama 的 `qwen3-embedding:0.6b`，1024 维。Docker 后端访问 `http://host.docker.internal:11434/v1`。MODEL_API_KEY 使用 SDK 所需的占位值 `ollama`，本地 Ollama 不使用此值鉴权；不是云平台密钥。配置文件仍由 Git 忽略。

日常使用先打开 Ollama，再启动 Docker 项目。模型首次加载可能较慢：本次第一次调用在加载阶段触发 30 秒超时，单独预热后成功，项目调用恢复正常。可在 Windows PowerShell 预热：

```powershell
Invoke-RestMethod -Uri 'http://127.0.0.1:11434/api/embed' -Method Post -ContentType 'application/json' -Body '{"model":"qwen3-embedding:0.6b","input":"warmup","keep_alive":"30m"}' -TimeoutSec 120 | Select-Object model
```

预热命令允许等待 120 秒，模型随后驻留 30 分钟；项目接口继续保持原有 30 秒超时且不自动重试。若再出现超时，先确认 Ollama 正常完成加载后再查询。

这份地址配置用于当前 Docker 启动方式；WSL 的 localhost 与 Windows 不同，本次已观察到直接访问 WSL localhost:11434 不通。不要直接把 Docker 地址套用到原生 WSL 运行。

Docker 将 Milvus 路径覆盖为 `/app/data/milvus/cases.db`，对应宿主机 `data/milvus`。配置文件只读挂载，密钥不进入镜像。

在 WSL 的 `/mnt/e/oshino` 中，填写配置后执行：

```bash
docker compose --env-file .env.docker stop backend
docker compose --env-file .env.docker run --rm --no-deps backend python -m app.rebuild_cases --replace
docker compose --env-file .env.docker up -d --wait backend
```

重建失败也要执行最后一条启动后端。未完成的索引不会作为成功结果使用。重建仅替换派生索引，不删除 PostgreSQL 工单。Milvus Lite 按单后端进程使用，重建时必须停止后端。

标题、问题和方案摘录会发送到配置的 Embedding 服务；不专门拼入客户姓名和邮箱，但正文中的个人信息不会自动脱敏。

## 验收步骤

1. 打开任意工单详情，点击“检索相似案例”。
2. 检查最多五条、没有当前工单、均有解决方案，点击出处能打开原工单。
3. 同模块不足五条时显示分类补查提示。
4. 缺少配置、索引或模型请求失败时显示错误，不显示虚构案例。
5. 修改已索引的案例后再次查询，旧候选应被排除；重建索引后才参与新检索。

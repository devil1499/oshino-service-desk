# 第六部分：知识库导入与检索

## 设计与实施顺序

沿用已有第六部分教程，由主代理在 XM 分支实施，不提交、不推送。

1. 外部边界支持 UTF-8 Markdown / TXT，最多 256 KiB，正文 1—100000 字符；管理员录入、上传、保存草稿、发布、停用。
2. PostgreSQL 新增文档及分块两表，发布时按 500 字符、80 字符重叠分块；草稿编辑会撤销旧发布内容。
3. 案例与知识共享 Milvus 建库和查询实现，保留原案例集合、元数据和现有索引。
4. 独立命令只重建已发布知识。复用本地 Ollama，不新增模型或 Python 依赖。
5. 知识页、编辑阅读页和工单详情接入真实 API，保持现有浅色样式。客服只读已发布资料，管理员管理草稿与停用资料。
6. 以公开 API、真实临时 PostgreSQL / Milvus、模型 HTTP 边界测试验证行为；最后使用真实本地模型和浏览器验证。

## 用户验收步骤

1. 打开 `http://127.0.0.1:18734/knowledge`，查看 4 篇已发布模拟资料，搜索 E401。
2. 打开 `http://127.0.0.1:18734/tickets/41`，点击“检索知识文档”，检查账号登录规范，点击标题核对原文。
3. 管理员新建文档，上传 UTF-8 的 `.md` 或 `.txt`，选择产品、模块、分类，保存草稿后发布。
4. 新增或修改文档发布后，按照第六部分教程的 Docker 命令停止后端、重建知识索引并启动后端。重建只替换知识集合，保留案例集合。
5. 停用文档后再次检索，该资料不应出现。

模拟资料用于毕业设计演示，不代表真实产品操作规范。

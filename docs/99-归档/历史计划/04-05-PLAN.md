# 第四、第五部分实施计划

目标：在已验证的第三部分上提供两个完整、可跟写的参考版本，不修改正式工程。用户已确认第四部分为模拟数据与 CSV 导入，第五部分为 Embedding 与 Milvus 混合检索。

架构：延续 FastAPI、SQLAlchemy、Vue；PostgreSQL 保存业务事实，Milvus Lite 保存可重建的案例检索索引。只处理有效历史案例，知识文档、模型重排和建议生成由后续部分接入。

## 第四部分

- [x] 在 tests/test_import.py 先通过 POST /api/tickets/import 验证导入后可查询，先确认接口尚未实现时的 405 失败，再实现。继续覆盖非法 CSV、权限、整批回滚与重复编号冲突。
- [x] 新增 modules/tickets/import_csv.py：UTF-8 CSV，最多 4 MiB / 5000 条；固定字段 import_key/title/description/customer_name/customer_email/product/module/category/priority/status/solution。管理员导入；支持 pending 与 resolved，后者必须有方案，前者不得伪装已有方案。配置按现有名称精确匹配并检查启用。
- [x] models.py 与新迁移为 tickets 增加可空、唯一的 import_key；历史工单保持不变。整批预校验后在一个事务中写工单与 imported 记录；重复编号返回 409。
- [x] app/demo_data.py：固定随机种子生成明确标注为模拟的 SaaS 工单，标准库 CSV 正确处理逗号和换行；输出文件已存在则拒绝覆盖。提供 40 条可直接查看的样例。
- [x] 前端 api/http.ts 支持已有真实调用需要的 FormData；新增管理员导入页面、路由与入口，显示导入结果和错误。

## 第五部分

- [x] integrations/embeddings.py 使用 OpenAI 兼容 Embedding API；超时 30 秒、禁用自动重试，边界验证响应条数、索引、维度和有限数值；模型和密钥显式配置。通过 HTTP MockTransport 验证适配器成功和失败。
- [x] integrations/case_index.py 使用已安装 Milvus Lite 3.2.2、PyMilvus 3.0.2、Jieba 中文分词；COSINE + BM25 + RRF。先通过真实临时 Milvus 测试两个召回通道及元数据过滤。
- [x] app/rebuild_cases.py 停后端后全量重建派生索引，成功后才写就绪元数据；失败不留下可用标记。索引记录模型、端点、维度和时间；更换模型要求重建。模型调用不包含客户姓名与邮箱。
- [x] modules/analysis/router.py 暴露 POST /api/tickets/{id}/similar，登录用户可调用。同产品模块优先，少于 5 条再扩大至同分类；最多返回 5 条，排除自身。返回前核对 PostgreSQL 当前状态和内容指纹，丢弃失效案例并提示重建。
- [x] 前端工单详情增加相似案例按钮、出处链接、方案、排序分数与索引时间；单独说明分数不是概率。索引缺失、配置错误、上游错误不能伪装成无结果。

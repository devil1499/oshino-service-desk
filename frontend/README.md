# 前端工作台

沿用教程中的深色工作台方向，基于现有 Vue 3、TypeScript、Pinia、Vue Router 和 Element Plus 搭建。此轮只修改前端，不新增后端接口或数据库迁移。

## 页面与数据来源

| 页面 | 路径 | 数据来源 |
|---|---|---|
| 工单列表、搜索筛选、分页 | `/tickets` | 明确标注的本地演示 |
| 新建工单 | `/tickets/new` | 本地演示；校验字段后创建 D 开头的编号 |
| 详情、记录与状态流转 | `/tickets/:id` | 本地演示，关闭后只读 |
| 工作概览 | `/dashboard` | 从同一份演示工单实时计算 |
| 知识搜索、阅读与新建草稿 | `/knowledge` | 本地示例文章及当前会话草稿 |
| 管理员/客服登录 | `/login` | 现有真实后端 |
| 基础管理 | `/admin` | 现有真实后端，要求管理员身份 |
| 连接检查 | `/health` | 真实 `/api/health` |

无需登录即可浏览演示页面；这不会创建令牌或绕过真实管理接口的鉴权。登录页仍使用原有管理员/客服账号，登录信息仅保存在内存。

演示工单、处理记录、知识草稿只保存在 Pinia 内存中，刷新页面即重置；不写 localStorage、数据库或文件，不自动回退或冒充真实后端响应。示例客户邮箱使用 `example.com`，没有邮件、AI、OCR 或真实检索调用。真实基础管理页有单独的数据来源提示。

## 运行

在 WSL Ubuntu-22.04 中：

```bash
source "$HOME/.nvm/nvm.sh"
nvm use 24
cd /mnt/d/xiangmu/oshino/frontend
npm run dev -- --port 18734
```

打开 <http://127.0.0.1:18734/tickets>。沿用已安装的依赖，不需要重新安装；换环境时使用配套锁文件执行 `npm ci`。仅演示页面可在后端未启动时使用；真实登录、基础管理和连接检查仍需要原有后端。

WSL 下开发服务使用文件轮询监听，确保从 Windows 编辑 `/mnt/d` 挂载盘中的代码后也能刷新页面；其他环境沿用 Vite 默认监听。

## 检查

```bash
npm test
npm run build
```

`build` 包含 TypeScript 检查。`npm test` 使用 Node 24 自带测试运行器，覆盖演示表单校验、状态顺序、关闭后只读、记录追加及种子数据隔离。

## 主要文件

- `src/App.vue`、`components/AppSidebar.vue`：工作台壳层、导航与移动端布局。
- `src/style.css`：主题变量与响应式样式；已有真实管理页面也沿用该主题。
- `src/demo/workspace.ts`：明确独立的演示类型、示例数据和本地状态规则。
- `src/stores/workspace.ts`：本地演示状态；不修改真实账号和配置。
- `src/api/`、`stores/auth.ts`：保留的真实接口及鉴权逻辑。
- `src/views/`：各页面，路由按需加载。

以后接入工单或知识后端时，应将对应页面改为真实 API 数据流，移除演示提示与演示 store 的依赖，不应把网络失败静默转换为演示成功。当前示例不代表真实业务端到端验收。
